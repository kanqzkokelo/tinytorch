# MoE inference implementation notes (2026-08-26)

Agent study of local oracle llama.cpp source (file:line cites inline).

## GGUF layout
- Router: `blk.%d.ffn_gate_inp` 2D [n_embd, n_expert] F32 (+optional bias).
- Experts: `ffn_up_exps`/`ffn_gate_exps` {n_embd, n_ff, n_expert},
  `ffn_down_exps` transposed {n_ff, n_embd, n_expert} — expert dim ne[2],
  one contiguous 2D matrix per expert.
- Variants: merged ffn_gate_up_exps (gemma4/qwen35moe), per-expert scales _s,
  exp_probs_b selection bias (DeepSeek-style).

## Decode mechanics (mul_mat_id)
ggml.c:3315: per output row picks expert ids[e,t]. CPU path builds
(token,slot)→expert map then runs THE SAME quantized vec_dot GEMV used by
dense decode per selected expert. CUDA decode path (ne2≤8): MMVQ kernels
indexed by ids — small-batch GEMV per expert-row. No masked batched GEMM,
no wasted compute. **One token = k small GEMVs against strided expert slabs.**

## Router (llama-graph.cpp:1941)
gate_inp@cur → gate op ∈ {softmax, sigmoid, softmax_weight, sqrt_softplus}
→ top-k argsort → optional weight-norm + routed_scaling. Shared expert =
separate dense FFN added after routed sum (gemma4 A4B: parallel shared-MLP +
routed branch with custom pre-scaled logits). Our existing dense MLP block IS
the shared-expert implementation.

## Quantization
Standard quant types per expert tensor; no special formats. imatrix normalized
per-expert counts at convert time. Scales/biases stay F32.

## Bandwidth model
bytes/token ≈ (k/n_e)·FFN bytes + router + attention. Qwen3-30B-A3B touches
~3B/30B params → ~10× bandwidth cut vs dense.

## Engine fit (kernels/qwen2_cuda.cu)
Add pl_moe[MAX_LAYERS] + per-layer {router/gate/up/down device ptrs, n_exp, k}
beside existing pl_* arrays. Reusable as-is: tt_gemv_typed (router + k×3 expert
projections), k_swiglu_apply, k_add, k_rmsnorm. NEW code only: top-k kernel
(single-block bitonic or host argmax for small n_exp) + weight-norm.
Heterogeneous geometry pattern extends naturally.

## Risks
Merged vs split gate_up layouts; llama4 pre-FFN weighting; varying n_exp/k per
layer; GGUF expert-slab stride padding; w_scale plumbing for sigmoid-no-norm
models. Note: gemma4 26B-A4B support becomes reachable once M8 forward is
parity-green — same trait machinery.
