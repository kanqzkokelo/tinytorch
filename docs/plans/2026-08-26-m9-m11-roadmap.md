much broader hardware support; speculative decoding (ngram first, DFlash2-capable).

## M10 — speculative decoding
Research verdicts (2026-08-26, agent-sourced):
- DFlash2 = trained block-diffusion drafter w/ KV-injection conditioning +
  Viterbi candidate-path selector (arXiv:2602.06036, z-lab/dflash, vLLM PR
  #52816, llama.cpp `draft-dflash`). Needs distilled drafter PER TARGET MODEL.
  Parked until we host 7B+ targets; plumbing below keeps the door open.
- ngram family = draftless, ~100 LOC, zero model cost. llama.cpp variants:
  simple (n=12 window, propose m), map-k (hash→mgram, min-hits), map-k4v,
  mod (LCG rolling hash, 16MB const). Wins: code-edit/summarize/RAG 2–4×;
  open-ended chat ≈0. Lookahead/Jacobi: bad fit for 4GB single-batch.

Build order:
1. Spec-decode skeleton: linear-chain draft → ONE batched verify forward
   (k+1 positions, causal) → greedy accept loop → KV rollback to first mismatch
   (pattern: llama_memory_seq_rm equivalent = reset d_pos + memset tail slots).
   Engine needs: multi-position forward (already exists = prefill path),
   per-slot logits extraction, cache truncation helper.
2. ngram-simple table: last-n window match over prompt+generated ring buffer.
3. Adaptive draft length from accept-rate stats (skip drafting when cold).
4. Graph capture per verify shape k+1 (launch overhead would eat the gain).
5. Rejection sampling for temp>0 (later; CLI is greedy-first).
6. DFlash2/EAGLE drafter interface: pluggable "draft source" behind the same
   verify loop — implement interface now, drafter loaders later.

## M11 — hardware breadth
- CPU backend: dequant_ref.c already portable; add CPU GEMM (quant-aware,
  OpenMP threads); dispatch table backend-agnostic.
- Vulkan backend: the real breadth answer. Decision needed: replicate CUDA-graph
  capture semantics via vkCmd buffers, or restructure engine around explicit
  command recording. Big design doc required before code.
- Metal/ROCm: after Vulkan proves the abstraction layer.
